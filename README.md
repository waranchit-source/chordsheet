# ระบบเนื้อเพลงและคอร์ด (Lyrics & Chords)

ระบบแบ่งเป็น 2 ส่วน

| ส่วน | อยู่ที่ไหน | หน้าที่ |
|---|---|---|
| หน้าเว็บ (Frontend) | GitHub Pages: https://waranchit-source.github.io/chordsheet/ (ไฟล์ในโฟลเดอร์ `docs/`) | หน้าจอทั้งหมดที่ผู้ใช้เปิดใช้งาน |
| ระบบหลังบ้าน (Backend API) | Google Apps Script ที่ผูกกับ Google Sheet "Worship song" (ไฟล์ `.gs` ทั้งหมด) | อ่าน/เขียน Google Sheet สร้างไฟล์ Doc/PDF ใน Drive ตรวจสอบสิทธิ์ผู้ใช้ |

ข้อมูลทั้งหมดยังเก็บใน Google Sheet เหมือนเดิม หน้าเว็บบน GitHub เรียก Apps Script ผ่านลิงก์ Web app (ลงท้ายด้วย `/exec`)

## ย้ายระบบเดิมมาใช้ GitHub (ทำครั้งเดียว)

1. เปิด Google Sheet "Worship song" → **Extensions → Apps Script**
2. วางโค้ดใหม่ทับไฟล์เหล่านี้ทั้งไฟล์: `Code.gs`, `Config.gs`, `Auth.gs`, `Db.gs`, `Setup.gs`, `Songs.gs`, `Setlists.gs`, `Render.gs`
   (`Stats.gs`, `FontMetrics.gs`, `appsscript.json` ไม่มีการเปลี่ยนแปลง)
3. ลบไฟล์ HTML เดิม 4 ไฟล์ออกจาก Apps Script: `Index`, `Styles`, `Chords`, `App` (คลิกจุด 3 จุดข้างชื่อไฟล์ → Delete)
4. กด **Save project**
5. เลือกไฟล์ `Setup.gs` → ฟังก์ชัน `setup` → กด **Run** หนึ่งครั้ง ระบบจะเพิ่มคอลัมน์ `Status`, `ReviewedBy`, `ReviewedAt` ในชีต `Users` และสร้างชีต `Sessions` (ข้อมูลเดิมไม่หาย ผู้ใช้เดิมทุกคนยังเข้าระบบได้ตามปกติ)
6. กด **Deploy → Manage deployments** → เลือก deployment เดิม → ไอคอน **ดินสอ (Edit)** → Version: **New version** → **Deploy**
   ต้องเป็น Execute as: **Me** และ Who has access: **Anyone**
7. คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`) ไปใส่ใน `docs/config.js` ที่ค่า `API_URL` แล้ว push ขึ้น GitHub
8. เปิด https://waranchit-source.github.io/chordsheet/

ลิงก์ `/exec` เดิมจะแสดงหน้าแจ้งให้กดไปที่ลิงก์ใหม่ (ตั้งค่าได้ที่ `FRONTEND_URL` ใน `Config.gs`)

## ติดตั้งใหม่ทั้งหมด (กรณีเริ่มจากศูนย์)

1. สร้าง Google Sheet ใหม่ → **Extensions → Apps Script**
2. สร้างไฟล์ Script ตามตารางด้านบน (เฉพาะไฟล์ `.gs`) แล้ววางโค้ด
3. เปิด `appsscript.json`: **Project Settings (ไอคอนเฟือง)** → ติ๊ก **Show "appsscript.json" manifest file in editor** → วางทับทั้งไฟล์
4. รันฟังก์ชัน `setup` → **Review permissions** → เลือกบัญชี → **Advanced** → **Go to (ชื่อโปรเจกต์) (unsafe)** → **Allow**
5. ดู **Execution log** จะเห็น Username `admin` และรหัสผ่านที่ระบบสุ่มให้ (จดไว้)
6. **Deploy → New deployment** → Web app → Execute as: **Me** → Who has access: **Anyone** → **Deploy**
7. นำ Web app URL ไปใส่ใน `docs/config.js` แล้ว push ขึ้น GitHub

ถ้าลืมรหัส admin: เลือกฟังก์ชัน `resetAdminPassword` → Run → ดูรหัสใหม่ใน Execution log

## อัปเดตโค้ดหลังแก้ไข

- **แก้ไฟล์ `.gs`**: วางโค้ดใน Apps Script → Save → **Deploy → Manage deployments → Edit → New version → Deploy** (URL เดิมใช้ต่อได้)
- **แก้ไฟล์ใน `docs/`**: push ขึ้น GitHub branch `main` แล้ว GitHub Pages จะอัปเดตเองภายใน 1 ถึง 2 นาที
  ควรเปลี่ยนเลข `?v=` ท้ายชื่อไฟล์ใน `docs/index.html` ทุกครั้ง เพื่อให้เบราว์เซอร์โหลดไฟล์ใหม่

## การลงทะเบียนและการอนุมัติ

1. ผู้ใช้ใหม่กด **Request access** (ขอสมัครใช้งาน) ในหน้าเข้าสู่ระบบ กรอก Username ชื่อที่แสดง และรหัสผ่าน
2. ผู้ดูแลระบบจะเห็นตัวเลขแจ้งเตือนที่เมนู **Users** → แท็บ **Requests** เลือกสิทธิ์แล้วกด **Approve** หรือ **Reject**
3. ผู้ใช้เข้าสู่ระบบได้หลังจากได้รับการอนุมัติเท่านั้น (ถ้ายังรอ หรือถูกปฏิเสธ ระบบจะแจ้งข้อความให้ทราบ)
4. ผู้ที่ถูกปฏิเสธสามารถส่งคำขอใหม่ด้วย Username เดิมได้
5. ผู้ดูแลระบบยังเพิ่มผู้ใช้เองได้ที่ปุ่ม **Add user** (ผู้ใช้ที่ admin สร้างใช้งานได้ทันที)

## จดจำการเข้าสู่ระบบ (Remember me)

- ติ๊ก **Remember me** ตอนเข้าสู่ระบบ: อยู่ในระบบต่อบนอุปกรณ์นั้น 30 วัน (นับใหม่ทุกครั้งที่ใช้งาน) และจำ Username ไว้ให้
- ไม่ติ๊ก: ออกจากระบบเมื่อปิดเบราว์เซอร์
- กด **Sign out** จะลบการจดจำของอุปกรณ์นั้นทันที
- ถ้า admin ปิดใช้งานผู้ใช้ เปลี่ยนรหัสผ่านให้ หรือปฏิเสธ การจดจำ 30 วันของผู้ใช้นั้นจะถูกลบ (หน้าที่เปิดค้างอยู่จะใช้งานต่อได้อีกไม่เกิน 6 ชั่วโมง เหมือนระบบเดิม)
- ระบบเก็บเฉพาะค่า hash ของ token ในชีต `Sessions` ไม่เก็บรหัสผ่าน

## สิทธิ์ผู้ใช้

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| ดูอย่างเดียว (Viewer) | ดูเพลง เปลี่ยนคีย์บนจอ ดูประวัติ ดาวน์โหลดไฟล์ ดูสถิติ |
| ผู้นำเพลง (Worship leader) | ทุกอย่างของ Viewer + เพิ่ม/แก้ไขเพลง สร้างชุดเพลง สร้างไฟล์ |
| ผู้ดูแลระบบ (Admin) | ทุกอย่าง + ลบเพลง ลบชุดเพลง จัดการผู้ใช้ อนุมัติ/ปฏิเสธคำขอสมัคร |

"ชื่อที่แสดง" จะถูกใช้เป็นชื่อผู้นำเพลงในสถิติ

## วิธีพิมพ์เพลง (ไม่ต้องใส่วงเล็บแล้ว)

ระบบใส่วงเล็บ `[ ]` ให้เองตอนบันทึก และแสดงตัวอย่างทันทีขณะพิมพ์ การเปลี่ยนคีย์ใช้ได้เหมือนเดิม

- **เนื้อไทย**: พิมพ์คอร์ดไว้หน้าพยางค์ เช่น `Cร้องเพลง G/Bถวาย` หรือ `C ร้องเพลง G/B ถวาย` (เว้นวรรค 1 ช่องหลังคอร์ดได้)
- **เนื้ออังกฤษ**: พิมพ์คอร์ดไว้บรรทัดบนของเนื้อเพลง ให้ตรงกับตัวอักษรที่ต้องการ (ช่องพิมพ์ใช้ฟอนต์ความกว้างเท่ากัน จึงจัดตำแหน่งได้ตรง)
  ```
  G       D
  Amazing grace
  ```
- **บรรทัดดนตรี**: `Intro: C G/B F Gsus4` หรือ `Solo: Am7 Em7 F G x2`
- **หัวข้อท่อน**: `Chorus:` `Bridge:` `ท่อน A` (แสดงเป็นตัวหนา) · บรรทัดว่าง = แบ่งท่อน และเป็นจุดที่ระบบเลือกตัดคอลัมน์
- **วางเพลงจาก Word** ที่คอร์ดอยู่บรรทัดบน: วางลงช่องที่ว่างอยู่ ระบบจะจัดรูปแบบให้เอง หรือกด **Tidy up chords** แล้วตรวจตำแหน่งในตัวอย่าง (เนื้อไทยจะถูกย้ายคอร์ดมาไว้หน้าพยางค์ แก้ตำแหน่งได้ง่าย)
- แบบเดิม `[C]ร้อง[G/B]เพลง` ยังใช้ได้ เพลงเดิมทั้งหมดไม่ต้องแก้ไข เปิดแก้ไขแล้วบันทึกโดยไม่เปลี่ยนอะไร เนื้อเพลงในชีตจะเหมือนเดิมทุกตัวอักษร

## ภาษาและธีม

- ภาษาเริ่มต้นเป็นภาษาอังกฤษ กดปุ่ม **ไทย** ที่มุมขวาบน (หรือในเมนูบนมือถือ) เพื่อเปลี่ยนเป็นภาษาไทย กด **English** เพื่อกลับ ระบบจำภาษาที่เลือกไว้
- ปุ่มพระจันทร์/พระอาทิตย์ สลับธีมมืด/สว่าง (ค่าเริ่มต้นตามเครื่อง)

## การจัดหน้ากระดาษ

- **อัตโนมัติ**: ถ้าเพลงพอดีครึ่งหน้า จะวาง 2 เพลงต่อหน้า (ซ้าย/ขวา) ถ้าเพลงยาวเกินครึ่งหน้า จะใช้ทั้งหน้าโดยแบ่งเป็น 2 คอลัมน์ ถ้ามีบรรทัดยาวเกินครึ่งหน้า จะใช้ทั้งหน้าแบบคอลัมน์เดียว
- **ครึ่งหน้า / เต็มหน้า**: บังคับเองได้ทั้งตอนตั้งค่าเพลง และในแต่ละชุดเพลง
- หลังสร้างไฟล์ ระบบจะแสดงว่าแต่ละหน้ามีเพลงอะไรบ้าง

## PDF / Word

- ไม่มีคำอธิบาย → ได้ **PDF** เก็บในโฟลเดอร์ `Chord Sheet Files/PDF`
- มีคำอธิบาย (ของชุดหรือของเพลงใดเพลงหนึ่ง) หรือเลือก Word เอง → ได้ **Google Doc** เก็บใน `Chord Sheet Files/Docs` เปิดแก้ใน Google Docs หรือดาวน์โหลดเป็น .docx ได้
- แก้ Doc เสร็จแล้ว กด **Finished editing, create PDF** หรือกด **Create PDF from Doc** ในหน้าประวัติ ไฟล์ PDF จะไปอยู่ในโฟลเดอร์ PDF
- ไฟล์ตั้งค่าให้ "ทุกคนที่มีลิงก์" เปิดได้ (PDF = ดูอย่างเดียว, Doc = แก้ไขได้) เพื่อให้ผู้ใช้ที่ล็อกอินด้วย username ของระบบเปิดไฟล์ได้
- ถ้าเปิดไฟล์ .docx ใน Microsoft Word ควรติดตั้งฟอนต์ Sarabun (ฟรีจาก Google Fonts) ไว้ในเครื่อง ไม่อย่างนั้นตำแหน่งคอร์ดจะเลื่อนเล็กน้อย

## ปรับแต่ง (Config.gs)

| ค่า | ความหมาย |
|---|---|
| `FRONTEND_URL` | ลิงก์หน้าเว็บบน GitHub Pages (ใช้ในหน้าแจ้งลิงก์ใหม่ของ `/exec`) |
| `REMEMBER_DAYS` | จำนวนวันที่จดจำการเข้าสู่ระบบ |
| `REGISTER_MAX_PER_WINDOW`, `REGISTER_WINDOW_SECONDS` | จำกัดจำนวนคำขอสมัครต่อช่วงเวลา (กันสแปม) |
| `LYRIC_SIZE`, `CHORD_SIZE` | ขนาดตัวอักษรเนื้อเพลง/คอร์ด (pt) |
| `TITLE_SIZE`, `HEADER_SIZE` | ขนาดชื่อเพลง/หัวกระดาษ |
| `MARGIN_*` | ระยะขอบกระดาษ (pt, 28.35 pt = 1 ซม.) |
| `LINE_HEIGHT_EM` | ค่าประมาณความสูงบรรทัด ถ้าเพลงล้นหน้าให้เพิ่ม ถ้าระบบตัดเป็นเต็มหน้าบ่อยเกินไปให้ลด |
| `CHORD_COLOR` | สีคอร์ด |
| `DRIVE_FOLDER_NAMES` | ชื่อโฟลเดอร์ใน Drive (ต้องแก้ก่อนรัน setup) |

## ข้อมูลในชีต

- `Songs` คลังเพลงทั้งหมด (ลบแล้วจะติดค่า Deleted = TRUE ไม่ได้ลบแถวจริง)
- `Setlists` ประวัติชุดเพลงทุกชุด พร้อมไฟล์และรายการเพลง/คีย์ที่ใช้
- `UsageLog` บันทึกการใช้เพลงทีละเพลง ใช้คำนวณสถิติ
- `Users` ผู้ใช้ (รหัสผ่านเก็บแบบ hash) คอลัมน์ `Status` = `pending` / `approved` / `rejected` (ช่องว่าง = approved สำหรับผู้ใช้เดิม)
- `Sessions` การจดจำการเข้าสู่ระบบ (เก็บเฉพาะ hash ของ token และวันหมดอายุ)

ไม่ควรแก้หัวคอลัมน์ในแถวแรกของทุกชีต
